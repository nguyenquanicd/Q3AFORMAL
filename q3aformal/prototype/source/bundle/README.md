# Q3AFormal Result Bundles

The Phase 0 result-bundle writer stores a portable, versioned record of a bounded-model-checking or supported k-induction run. The current bundle schema is `Q3A-RUN-BUNDLE-1`.

## Create a bundle

```powershell
$q3a = '.\prototype\bin\q3aformal-sourcecheck.exe'

& $q3a --bmc .\prototype\bmc-state-failure.q3a `
    --property p_q_tracks_a --frames 1 `
    --bundle-dir .\evidence\trial\bmc-run

& $q3a --prove-inductive .\prototype\known-pass-combinational.q3a `
    --property p_y_implies_a `
    --output-prefix .\prototype\bin\induction-evidence `
    --bundle-dir .\evidence\trial\induction-run
```

The bundle directory must be new. The writer stages its contents in a sibling directory and publishes the completed directory by rename. It refuses to overwrite existing evidence.

Bundles produced by the product command can include `reports/run-configuration.json`. The file records the initiating engine, property, search and resource limits, and resolved project identity. For a PDR witness, the bundle command and bound describe the bounded replay query. The configuration records the initiating PDR search options. The verifier checks the file digest and compares its source, model, property and bound context with the archive. Earlier bundles remain readable without this optional artifact.

## Reopen and revalidate

```powershell
& $q3a --verify-bundle .\evidence\known-pass\run-bundle-2026-11-16-v2
& $q3a --verify-bundle .\evidence\known-fail\run-bundle-2026-11-16-v2
```

The read-only verifier checks the manifest sidecar, every listed artifact size/hash, source snapshot identity, model identity, and query-to-CNF hash. For proof artifacts whose checker ID, schema, and source fingerprint match the current DRAT checker, it checks the exact CNF/proof pair against the recorded model and query identities. For BMC bundles with a saved witness, it reconstructs the supported serialized T-IR and independently replays the trace equations, assumptions, and target property. For no-witness BMC `BOUNDED_PASS` assertion results and `UNKNOWN` cover misses, it can regenerate the bounded query from serialized T-IR, require byte-for-byte CNF equality, check model feasibility, and rerun the UNSAT query when the recorded SAT bit-blaster component fingerprint matches. The cover result remains `NOT_FOUND_WITHIN_BOUND`; it is not `UNREACHABLE`. Successful proof, witness, or bounded-query revalidation reports `Q3A_BUNDLE_STATUS REVALIDATED` with the applicable scope. These checks apply to serialized T-IR and do not establish RTL-to-T-IR translation correctness. Bundles without compatible revalidation evidence remain `HISTORIC`. A hash, regenerated-query, or proof mismatch is an error, not a historic result.

For a re-executed bounded assertion pass, the verifier also determines whether any antecedent or guarded assertion is active within the saved bound. A replayed assertion failure supplies an active witness. The verifier emits `Q3A_BUNDLE_BMC_VACUITY VACUOUS` or `NONVACUOUS` and rejects a contradictory saved claim, even if the manifest and artifact hashes match.

Re-executing a bounded assertion pass or cover miss also checks the saved status of the temporal boundary. An incomplete horizon in the selected property or an assumption produces `Q3A_BUNDLE_BMC_BOUNDARY_OBLIGATIONS INCOMPLETE`. The bounded query may still establish its recorded result within that horizon.

An `INCONSISTENT_MODEL_OR_ASSUMPTIONS` bundle with a matching SAT component fingerprint is revalidated by regenerating its model-feasibility query, comparing the exact CNF, and reproducing `UNSAT`. The query includes the selected target's definitions and omits its assertion-violation or cover-hit constraint. The verifier also checks the temporal boundary and reports the same inconsistency status within the recorded bound.

The verifier compares the regenerated CNF's SHA-256 against the digest verified from the saved artifact. It hashes generated bytes through a 64 KiB buffer and avoids retaining either CNF as a complete string for this comparison. The regenerated solver clauses and model remain in RAM.

For checked induction evidence, the verifier opens the saved proof and CNF with writes denied. It rehashes both exact streams, rewinds them, and checks the proof through those same handles. This avoids allocating buffers proportional to the full certificate and CNF text sizes. The active clause database still occupies RAM.

Before accepting a checked induction obligation, the verifier also regenerates its canonical CNF from the saved model, assertion, depth and obligation kind. It uses the same encoder as proof generation and compares the streamed SHA-256 against the authenticated CNF digest. A saved `PROVEN` result requires separate checked base and step artifacts. Revalidation requires matching encoder and checker fingerprints. The independent DRAT checker validates unsatisfiability of the regenerated queries, and this scope remains the saved transition model.

For an induction countermodel, the verifier reads the saved witness and checks its identities, frame indices, signal widths and claimed failing sample. It then validates the trace against the saved model and the selected obligation. An assertion failure requires an accepted base witness. A non-inductive result requires an accepted step witness and a revalidated base certificate.

For a matching SAT component fingerprint, the verifier also regenerates the witness obligation's canonical CNF and emits `Q3A_BUNDLE_INDUCTION_WITNESS_QUERY VERIFIED`. This comparison uses the same encoder and streamed digest as a certified obligation. A legacy encoder may still permit independent trace replay, with the saved query marked `UNVERIFIED`.

During witness replay, the verifier derives the temporal boundary from the saved property's sample horizon and the assumptions, and checks that the trace length, run bound and query bound agree. For a matching SAT component fingerprint the verifier checks the boundary claim against this independent computation. For a legacy SAT fingerprint the witness can still replay, and its saved boundary is labeled `UNVERIFIED`.

`Q3A_BUNDLE_MODEL_CONTEXT VERIFIED` confirms that the manifest and property report list the same ordered assumptions as the saved Transition Intermediate Representation (T-IR). It also confirms the property's sampling clock and the supported reset and initial-state policy. New manifests record the sampling clock and positive edge in `sampling_context`. For older manifests, the verifier obtains the clock from the saved T-IR. Synchronous reset behavior comes from the transition equations. Reset labels supplied to the debug viewer are display annotations.

Bundle paths preserve hierarchical property names with generated-instance indices such as `g_lane[0].u_leaf.p_not_copy` and identifiers containing `$`. In PowerShell, pass a path containing brackets with `-LiteralPath` when using filesystem commands.

The `Q3A-PROPERTY-RESULT-2` report records sorted `signals.rtl` and `signals.model` lists for the selected property. Both include the sampling clock. The RTL list resolves generated history state back to the sampled operands, retaining elaborated design names and stopping at ordinary design drivers. The model list retains the direct T-IR references, including history data and guard state. Both lists cover the selected property individually. The verifier reconstructs the lists from the saved model and reports `Q3A_BUNDLE_PROPERTY_SIGNALS VERIFIED` on a match. Version 1 property reports remain readable.

For a compatible BMC witness, the verifier releases the decoded trace after replay and rebuilds the assertion-violation or cover-hit CNF. It checks the streamed digest against the saved query and emits `Q3A_BUNDLE_BMC_WITNESS_QUERY VERIFIED`. A legacy fingerprint preserves trace replay and labels the saved query `UNVERIFIED`.

When a BMC bundle includes a Value Change Dump (VCD), the verifier checks the archived waveform against the replayed witness. It checks the selected signal hierarchy and widths, sample indices, values, and declared sampling events. Source-backed verification also checks the packed ranges available from RTL. Legacy VCDs use timestamps for clock sampling. A match emits `Q3A_BUNDLE_VCD VERIFIED`. The verifier holds the waveform open with writes denied and compares one sample at a time.

Current source lowering writes T-IR `Q3A-TIR-0.4`, including separate antecedent/consequent `$past` history guards. The bundle verifier also accepts legacy T-IR `Q3A-TIR-0.3` models and replays them using their saved property-wide guard fields.

For a matching source pipeline, the verifier recomputes the resolved source-set digest from the archived source roster, top and parameters. It parses and elaborates the archived RTL bytes, lowers the result, and compares the serialized T-IR digest to the saved model. The source result is `Q3A_BUNDLE_SOURCE_MODEL VERIFIED` or `UNVERIFIED` for an older pipeline. This checks reproducibility with the recorded compiler components. Independent source-to-model conformance remains a separate verification activity.

Use `--verify-bundle <directory> --require-source-model` to recompile the archived sources with the current executable even when the saved compiler fingerprint differs. Exit 0 requires both `Q3A_BUNDLE_SOURCE_MODEL VERIFIED` and `Q3A_BUNDLE_STATUS REVALIDATED`. A mismatching model, evidence classified as historical, or an interruption record fails this mode. A compatible saved model can still be revalidated with the ordinary command and report `SOURCE_MODEL UNVERIFIED` if the compiler fingerprints differ. Strict verification regenerates bounded queries, witness queries, and induction obligations even across SAT encoder fingerprint changes. It requires the regenerated CNF digest to match the archived query bytes. A matching digest still requires the usual DRAT check, witness replay, or bounded query re-execution. The saved DRAT checker ID and artifact schema must remain supported. A different original checker build fingerprint is accepted in this mode only after the current checker validates the archived proof against the regenerated query.

## Contents

- `manifest.json`: schema, run and property status, profile, project/source identity, model identity, query records, assumptions, sampling context, reset/initial-state policy, build and component fingerprints, checker identity, resource limits, and hashes for every listed artifact.
- `manifest.sha256`: SHA-256 of the exact `manifest.json` bytes.
- `summary.json`: compact run status and query summary.
- `source-snapshot/project.q3a` and `source-snapshot/rtl/`: exact project manifest and RTL bytes, stored under manifest-relative paths.
- `model/model.json`: exact canonical T-IR supplied to the run.
- `queries/`: exact DIMACS CNF bytes used by the query or proof obligations.
- `properties/`: per-property result, replay-validated BMC trace, checked DRAT artifacts, and validated witnesses when those artifacts exist.
- `trace/`: optional VCD and self-contained HTML waveform viewer exported from a replay-validated BMC witness.

Resource-limit counters are recorded exactly as supplied by the run. A value of `0` means that limit is unlimited; it does not mean the resource was unused.

Artifact paths inside the manifest use `/` separators and are relative to the bundle root. The manifest includes each artifact's role, byte count, and SHA-256. It records the executable hash, deterministic build ID, compiler version, component source fingerprints, and the proof checker or replay checker identity.

Bundle creation and verification use native extended-length Windows paths for filesystem operations. Stored artifact paths keep their portable relative form. The Windows regression publishes and reopens an induction bundle with an output path longer than 260 characters and rejects attempts to overwrite that bundle.

The writer serializes bounded query CNF and replay trace JSON directly into staging. It copies exported waveforms and newly checked induction certificates in 64 KiB blocks and hashes streamed artifacts in the same block size. The staging index holds paths, roles, sizes and SHA-256 digests. The writer adds the manifest and its digest before publishing the completed directory. The solver and proof checker retain their active clause databases in memory.

The reader verifies every listed file size and SHA-256 in 64 KiB blocks. It keeps an index of verified paths, roles, sizes and digests. Proof checking loads one CNF/proof pair at a time. Replay loads the trace and model it needs. Each input loaded for a semantic check is checked again against its verified size and digest. See [the bundle evidence](../../corpus/results/t024-t026-result-bundles.md) for the measured effect on a bundle with a large passive attachment.

For contradictory assumptions, the bundle records the model-feasibility CNF and `INCONSISTENT_MODEL_OR_ASSUMPTIONS`; this does not claim functional coverage. A resource-limited feasibility query is recorded as `UNKNOWN`. BMC statuses remain bounded; only the k-induction flow for supported scalar or same-cycle overlapped implication invariants can report `PROVEN`, and its scope is `GENERATED_TIR_MODEL`.

## Current boundary

Bundle reopening revalidates compatible DRAT proof artifacts, replay-validates saved BMC witnesses, and can regenerate/reexecute no-witness bounded-pass assertion and bounded-cover-miss queries against the bundled T-IR when the SAT component fingerprint matches. Query reexecution is scoped to the serialized model: it does not reconstruct or validate RTL-to-T-IR semantics. A cover miss remains bounded and non-conclusive. Optional proof caching is limited to checked DRAT artifacts from supported k-induction queries; it is not a bundle cache and does not cache BMC results or SAT witnesses. The stored source/model evidence does not independently prove that RTL was translated correctly. See [proof-cache design](../cache/README.md).
