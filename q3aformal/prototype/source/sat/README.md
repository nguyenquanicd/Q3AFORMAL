# Q3AFormal SAT Core

Q3AFormal includes an internally implemented deterministic conflict-driven clause learning (CDCL) solver for conjunctive normal form (CNF). It uses two watched literals per clause, first unique implication point (1-UIP) conflict analysis, nonchronological backjumping, and a stable positive-first decision phase with conflict-activity tie breaking. It has no external solver dependency. Bounded model checking reuses a capped set of learned consequences from the feasibility solve after adding the permanent property goal. Watch and trail state are rebuilt each time. Standalone proof generation and temporary queries use the original CNF and fresh search state. Restarts and general learned-clause reduction are open.

## SAT solver and bit-blaster

The C++ API is in `sat_solver.hpp`. Variables are allocated explicitly, and literals use the signed DIMACS convention (`+n` for variable `n`, `-n` for its negation). The solver reports `SAT`, `UNSAT`, or `UNKNOWN`. Configured decision, propagation, and proof-record limits return `UNKNOWN` when exhausted. Optional `Limits::record_drat_proof` returns learned clauses and the final empty clause as a Reverse Unit Propagation (RUP) refutation for an UNSAT query without assumptions. Proof logging rejects assumption-based calls; encode assumptions as unit clauses in the exact CNF instead. Integrated induction caps proof logs at 1,000,000 records and discards incomplete logs.

Each solve reads the immutable base literals in place and allocates its own watch positions. Its learned clauses have stable storage owned by that solve. Feasibility, vacuity and property queries therefore reuse the base literal storage across calls. Assignments, learned clauses and watches are rebuilt per query.

`tir_bit_blaster.hpp` emits Tseitin CNF clauses for the current at-most-64-bit T-IR expression slice: constants, signals, concatenations, conditional expressions, one-bit logical operators, bitwise AND/OR/XOR/XNOR/NOT, equality and inequality, signed and unsigned relational comparisons, addition/subtraction, unary two's-complement negation, constant-distance `<<`, `>>`, and prototype `>>>`, normalized constant bit/part selects, and lowered `casez_match` nodes. Binary operands are extended to the maximum operand width; sign extension is used only when both operands are signed, otherwise zero extension is used. Conditional branches follow the same rule. Addition and subtraction truncate carry or borrow at the result width. Shift amounts must be compile-time nonnegative constants; logical shifts at least as wide as the left operand produce zero, while `>>>` sign-fills only for a signed left operand. Dynamic, nested, scalar, and out-of-range selects reject. Temporal `$past`, unsupported context-determined sizing, and unknown four-state literals reject with source-located errors. The `>>>` path is tested as a four-bit prototype extension but is excluded by the v0.10 profile specification until amended. This is a limited tested operator slice, not general IEEE 1800 sizing conformance. `encode_predicate`, `require_true`, and `require_false` provide one-bit property-constraint entry points.

`test_sat_arithmetic_shift_bitblast.ps1` exhausts four-bit logical and arithmetic-right-shift values/distances against an independent value oracle, then checks symbolic bit mappings for `<<`, `>>`, and `>>>` at widths 1, 4, 8, 16, 32, and 64 across boundary distances. The wider checks validate the SAT bit-blaster only; they do not establish source parser/lowerer or replay support at those widths.

## DIMACS interface

The diagnostic CLI accepts strict DIMACS CNF input:

```powershell
.\prototype\bin\q3aformal-sourcecheck.exe --sat-dimacs .\path\problem.cnf
.\prototype\bin\q3aformal-sourcecheck.exe --sat-dimacs .\path\problem.cnf --decision-limit 100000 --propagation-limit 2000000
.\prototype\bin\q3aformal-sourcecheck.exe --sat-dimacs .\path\problem.cnf --assume 5 --assume -12
```

The parser checks the `p cnf` header, declared variable and clause counts, literal range, and terminating zero for each clause. Repeated `--assume LIT` options add temporary unit literals to one solve call; assumptions are discarded when the call returns. Output uses `Q3A_SAT_STATUS`, `Q3A_SAT_STATS`, and, for satisfiable input, a DIMACS-style `Q3A_SAT_MODEL` line. A zero resource limit means unlimited. `UNKNOWN` exits with code 3, malformed input with code 1, and `SAT`/`UNSAT` with code 0. Before reporting `SAT`, the kernel checks the returned assignment against all stored clauses and assumptions.

## Transition and bounded-property queries

`transition_encoder.hpp` composes the bit-blaster with a lowered `Q3A-TIR-0.4` module. `--transition-cnf <project.q3a> --frames N` emits frames 0 through N: combinational equations hold in every frame, next-state equations connect frame t to t+1, RTL state at frame 0 remains unconstrained, and generated `$past` validity state is initialized false under the Phase 0 model contract. `c q3a_signal` comments map each signal bit and frame to a SAT variable. Multiple clocks, unsupported signal roles, missing or duplicate drivers, width inconsistencies, unknown T-IR references, and transition bounds above 10,000 reject.

`--bmc <project.q3a> --property <property-name> --frames N [--vcd <output.vcd>]` supports scalar assertions and assumptions, standalone linear sequence assertions, and linear finite implication sequences using `|->` or `|=>`, plus scalar, linear-sequence, and linear-implication cover goals. Standalone sequence assertions require at least one complete match path at each property-start frame; starts without the full horizon are marked incomplete. Sequence terms support fixed delays, finite literal or resolved-constant delay ranges `##[m:n]`, and positive bounded consecutive repetition. A finite delay range is lowered to a true-predicate repetition term, allowing the matcher to choose any legal endpoint. Unbounded delay ranges are unsupported. The query honors generated `$past` warm-up guards, reports vacuity and incomplete assertion-boundary obligations, and may report `BOUNDED_FAIL`, `BOUNDED_PASS`, `INCONSISTENT_MODEL_OR_ASSUMPTIONS`, `COVERED`, or `UNKNOWN`.

SAT counterexamples and cover witnesses are decoded and independently replayed against T-IR transition equations, assumptions, and the selected assertion or cover goal before reporting. Validated traces appear as `Q3A_BMC_TRACE_SIGNAL` rows and may be exported as Value Change Dump (VCD), with one discrete sample frame per nanosecond and abstract clock signals omitted. The bounded matcher rejects more than 4,096 path alternatives or 1,000,000 predicate-frame evaluations. An implication cover requires a complete in-bound antecedent and consequent match; vacuous success is not a reachability witness. A bounded pass is not an unbounded proof, and a cover miss is not an unreachability proof. This is not a complete IEEE assertion-monitor or coverage-counter implementation.

## K-induction

`--prove-inductive <project.q3a> --property <name> [--k K] --output-prefix <path>` constructs k-induction base-prefix and step obligations. It supports scalar predicates, same-sample `##0` sequences, standalone scalar assertion sequences, and `|->`/`|=>` implications whose one-bit linear operands use fixed delays, finite bounded delay ranges `##[m:n]`, and positive bounded repetition. Each sequence has at most 4,096 expanded match paths; the complete target horizon plus `k` must fit within 10,000 transitions. Assumptions support the same sequence subset and are constrained only at starts whose full maximum horizon fits the proof window. Delayed properties with guarded `$past`, unbounded delay ranges, non-linear automata, and other temporal forms are rejected.

Standalone sequence assertions must match at every property-start frame; an antecedent mismatch is a failure, not a vacuous implication. For each antecedent match endpoint, the consequent starts at that endpoint for `|->` or at the following frame for `|=>`. A sequence succeeds when at least one legal complete path matches. Incomplete temporal assumption tails are omitted consistently from encoding and replay. Base applies generated history-valid initialization; the step leaves frame-zero state unconstrained. The command writes `.base.cnf` and `.step.cnf`; checked UNSAT obligations also receive `.base.q3adrat` and `.step.q3adrat`. It reports `PROVEN` only after both obligations pass the separate DRAT checker. A replayed base witness reports `FAIL`; a replayed step witness reports `NOT_<k>_INDUCTIVE` because it may be unreachable. A witness that fails replay reports `UNKNOWN`.

The proof result applies to the generated T-IR model and does not establish that frontend/lowering matches IEEE 1800 semantics. SAT model search is limited to 1,000,000 decisions and 10,000,000 propagations; proof search has separate node, record, variable, and depth limits. Reaching a limit reports `UNKNOWN`.

## Validation evidence and remaining scope

Focused tests include `test_sat_cdcl.ps1`, `test_sat_relational_bitblast.ps1`, `test_sat_arithmetic_shift_bitblast.ps1`, `test_transition_cnf_frames.ps1`, `test_bmc_property_queries.ps1`, `test_sequence_bmc_bitblast.ps1`, `test_property_replay.ps1`, `test_inductive_sva_implication.ps1`, and `test_inductive_proof.ps1`. These tests cover selected solver, expression, transition, bounded-query, replay, and induction cases. General solver validation, incremental frame extension, complete SVA monitor semantics, broad source-to-T-IR conformance, full-profile replay and proof integration, and generalized unbounded induction remain open.

The normal Windows build compiles this module into `prototype/bin/q3aformal-sourcecheck.exe`; no third-party solver library is linked. The separate proof utility is documented in [`prototype/checker/README.md`](../../checker/README.md).
