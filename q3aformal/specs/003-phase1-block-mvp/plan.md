## Sequential property batch

`prove-batch <project.q3a> --plan <file.q3b> --output-dir <new-directory> [--cancel-file <path>]` loads the project once and runs the declared property jobs in order with one worker. The bounded plan format starts with `Q3AFORMAL_BATCH 1`, followed by `memory_mib <limit>` and up to 128 records in the form `job <id> <engine> <property> <depth> <timeout_ms>`. Version 1 uses a common process-private memory cap with a separate deadline for each job. Each engine enforces the tighter of the plan and the existing memory policies at its existing checks. The manifest and source read prior to job scheduling is outside those engine checkpoints. Version 2 accepts the same required records and allows a PDR job to append `max_queries N`. The option applies only to that job. The aggregate report retains the declared option for a cancelled or pending job. The effective limit appears in a resolved PDR result. Interruption records preserve their existing schema.

The batch writes each product run record to `job-<id>/result.json`, using separate evidence paths. It records the plan digest, exact source-set digest, build identity, worker count and declared memory limit in `batch.json`. The aggregate exit code is the maximum job exit code for a batch that reaches the end. A cancellation reports exit 1, identifies the interrupted job, and marks later jobs `NOT_RUN`. PDR searches over the one-clock, two-valued transition model for an assertion or cover goal under same-sample or finite temporal assumptions.
